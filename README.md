# Experimental Design & Analysis in Biology — course site

A [Quarto](https://quarto.org) website for BIOL 4860/5860 (Experimental Design and Analysis), UMass Lowell, Spring 2027.

Weeks skip from 7 to 9 (Week 8 is Spring Break) and stop at 14 (Week 15 is final project presentations, with no slides/tutorial/assignment files of its own).

## Opening the project in RStudio

1.  Unzip this folder.
2.  In RStudio: **File → Open Project...** and select `exp_design_course.Rproj`.
3.  Open any `.qmd` file and click **Render**, or render the whole site from the **Build** pane / Terminal:

``` bash
quarto render
```

4.  Preview with live reload while editing:

``` bash
quarto preview
```

## Publishing

``` bash
quarto publish gh-pages
# or
quarto publish quarto-pub
```

`_quarto.yml` renders into `docs/`, which is what GitHub Pages expects when serving from the `main` branch's `/docs` folder.

## Design system

The site uses a custom theme rather than a stock Bootswatch look. The active theme is **bold** (`styles-bold.scss`, referenced in `_quarto.yml`):

- **Palette:** white background (so R plots, which render on a white panel, sit flush rather than looking boxed), near-black ink, and a bold accent color (currently emerald green) — defined as the `$accent` and `$accent-dim` Sass variables near the top of `styles-bold.scss`. That's the only place you need to edit to change the site's accent color everywhere at once.
- **Type:** `Space Grotesk` (bold, geometric) for headings, `Inter` for body text, `IBM Plex Mono` for code — loaded via `partials/fonts.html`. IBM Plex Mono is used deliberately because it has no ligatures — R's `|>` and `<-` render as literal characters instead of being merged into arrow glyphs.
- **Layout:** a single \~760px reading column, thick rules (navbar border, table header, callout bars) rather than hairlines, and a bold black table header row

A quieter alternate theme (`styles.scss`) — same white background and type choices, but a muted pine-green accent, serif headings, and hairline rules instead of bold blocks — is also included but not currently referenced. To switch back to it, change the `theme:` list in `_quarto.yml`'s `format.html` section from `styles-bold.scss` to `styles.scss`.

To adjust either theme's look, edit the `scss:defaults` variables at the top of the relevant file (colors, fonts, sizes) before touching the `scss:rules` section below them.

## Assignment downloads and PDF submission

Assignments and Data Safari files use `format: typst` in their own front matter (overriding the site's default HTML format), so rendering them produces a PDF instead of a webpage — Typst is bundled with Quarto, so this needs no separate LaTeX install for you or your students.

Three things make this work end-to-end:

- **`scripts/build-templates.R`**, run as a `pre-render` step (see `_quarto.yml`), copies every `assignments/*.qmd` file into a separate `templates/` folder before each render.
- **`templates/*.qmd` is excluded from `render:`** (via the `"!templates/*.qmd"` entry) but included in `resources:`, so Quarto copies those files into `docs/templates/` verbatim without ever treating them as documents to render.
- **`schedule.qmd`'s download links** point at `templates/weekNN-*.qmd` (not `assignments/weekNN-*.qmd`) using raw HTML anchors (`<a href="..." download="...">`) rather than plain Markdown links — a plain Markdown link to a `.qmd` path gets automatically rewritten by Quarto to point at that file's rendered output instead, which is not what a "download the template" link should do.

**Why the separate `templates/` folder, instead of just copying `assignments/*.qmd` directly into `docs/`:** an earlier version of this site did exactly that, and a student reported downloading a link labeled `week02-assignment.qmd` that turned out to actually contain the rendered PDF's bytes under a `.qmd` extension — a same-path collision between the raw resource copy and that file's own rendered output, which we could not reliably reproduce but also could not rule out for every Quarto version or preview scenario. Routing downloads through `templates/`, a path with **no corresponding render target at all**, removes the ambiguity entirely: there is no output for Quarto to ever confuse the static copy with.

If you add a new assignment file, add it under `assignments/` as usual (with `format: typst`) — the pre-render script picks up anything matching `assignments/*.qmd` automatically, so `templates/` never needs manual editing (and any manual edits there would be overwritten on the next render anyway).

For everything else (tutorials, syllabus, schedule, slides' HTML chrome — anything that stays in the site's normal HTML format), `code-tools: true` in `_quarto.yml` adds a **Code → View Source** menu in the top right of the page, letting students view or save the page's own `.qmd` source without any special setup.

## Customizing content

- **Navbar items:** edit `website.navbar` in `_quarto.yml`. Individual weekly files are intentionally *not* in the navbar (43 files would make an unusable dropdown) — `schedule.qmd` is the hub that links to all of them.
- **Course details:** `index.qmd`, `syllabus.qmd`, and `schedule.qmd` hold the meeting time, instructor info, and week-by-week topics — keep these three in sync if the schedule changes.
- **Add or change a week:** each week has up to four files — `lectures/weekNN-slides.qmd`, `lectures/weekNN-tutorial.qmd`, `assignments/weekNN-assignment.qmd`, and (Weeks 4, 7, 10, 13 only) `assignments/weekNN-data-safari.qmd`. Update `schedule.qmd`'s table to match whenever you add, remove, or renumber a week.
- **Slide decks** (`lectures/weekNN-slides.qmd`) use Quarto's `revealjs` format rather than the site's normal HTML format, and share `partials/slides.scss` for theming. Open the rendered `docs/lectures/weekNN-slides.html` directly (or via the Schedule page) to present — use arrow keys or click to advance slides.
- **Graduate project checkpoints** (`assignments/project-0N-*.qmd`) follow the same `format: typst` pattern as weekly assignments, with due dates set in the Schedule page's project-milestones table and in `assignments.qmd`, not in the files themselves.

> **Avoid callout blocks (`::: {.callout-*}`) in any `format: typst` file.** Quarto's Typst template pulls in a `fontawesome` package from the internet the moment a document contains a callout, which fails without network access (or behind a restrictive firewall). Weekly assignments and project files use plain **bold-lead-in** text instead (e.g. `**Note:** ...`) for asides that would otherwise be callouts — follow that pattern for new Typst files. Callouts remain totally fine in the site's regular HTML pages (syllabus, schedule, tutorials).

## Notes

- `execute.freeze: auto` in `_quarto.yml` caches code output so re-rendering the whole site doesn't re-run every chunk unless the source has changed.
- `.gitignore` excludes `.quarto/`, `.Rproj.user/`, and other local build/session files — `_freeze/` is intentionally *not* ignored, so cached results travel with the repo.
